# Video & Pipeline Improvement Report — `demo_video/edited.mp4`

Scope: the shipped 47.51s vertical deliverable rendered by
`server/render_flow_only_master.py`, plus the render pipeline that produced
it. Findings below are anchored to values actually measured from the file
and from the repository's own transcript artifacts
(`storage/deliverables/voxpipe_0901_profitbricks/`), not estimated.

## 1. Measured facts

| Codec | H.264 (video) / AAC (audio) | `ffprobe` |

**Audio is close to spec (−14 LUFS target, actual −13.67) and safe (true
peak below −1.0 dBTP).** The visual cadence is the real gap: several shots
run 4.4–8.2 seconds without any framing change, roughly double the skill's
own target interrupt interval.

## 2. Root-cause findings in the codebase

### 2.1 `render_flow_only_master.py` is a single-use, non-portable script

- Every path is hardcoded to one Windows machine: `work_dir = Path(r"c:\websites\ai video production tool\...")`, `src_vid = r"D:\Downloads\0901.mp4"`, fonts read from `C:\Windows\Fonts`. This file cannot run on any other machine, including this one, without editing source.
- Missing-asset handling is a bare `sys.exit(1)` inside the clip-loading loop (`server/render_flow_only_master.py:64-66`) — a mid-startup crash with no aggregated report of *everything* that's missing.
- Subtitles are hand-typed fixed strings (`SUBTITLES` list, lines 113–128) with no width check against the actual rendered font metrics, so a longer line in a future video would silently overflow the caption card.
- The outro card cuts in/out hard with no fade (`OUTRO_FLOW` branch, lines ~200–213).
- There's no post-render QC step in this script at all — `finalize_*`, `verify_master_video.py`, and similar one-off scripts exist elsewhere in `server/`, but this specific render path emits nothing machine-checkable.

### 2.2 The transcript/caption pipeline silently fails on this exact audio

`storage/deliverables/voxpipe_0901_profitbricks/word_timestamps.json` (the
Whisper-based ASR output the repo generates for this deliverable) is
unusable:

- Word confidences in the first 2.7s are 0.23–0.54 and the transcribed text is not real Hindi ("प्र्ठ़द", "वौबट", "हैँगिं").
- From 22.14s to 44.64s — the exact span covering the longest static hold plus the following two shots — word-level alignment collapses into three tokens ("पर", "सकते", "हैं") each artificially stretched across seconds. This is a >22-second alignment failure in the one segment most in need of caption accuracy.
- `transcript_clean.json` confirms the same failure at the sentence level: one entry spans `19.3s → 44.54s` (25 seconds) as a single garbled sentence.

**Conclusion:** the captions actually shown in the shipped video were typed
by hand into `SUBTITLES`, not generated by the transcript pipeline — which
is good for this one video, but means the automated captioning path is
silently broken and would produce nonsense if anyone tried to use it for
the next video without noticing.

### 2.3 No connection between the "reference" pipeline and this deliverable

`server/app/editor/production_v4.py` is a typed pipeline invoked through
`production_editor.py` with `plan` → `generate` → `assemble` → `review` →
`approve` stages, each of which reads/writes a `production-job.json` and
(for other deliverables) an `EditPlan.json` + `qc_report.json`. The
`voxpipe_0901_profitbricks` directory that backs this video has **no**
`EditPlan.json` and **no** `qc_report.json` — only transcripts. This
deliverable was produced entirely outside the typed/QC'd pipeline, by a
one-off script living directly in `server/`, one of ~80 similarly-named
`render_*`/`produce_*`/`finalize_*` scripts in that directory.

## 3. What `server/render_master_v4.py` fixes

| # | Issue | Fix |
|---|---|---|
| 1 | Hardcoded machine paths | All inputs are CLI args (`--source`, `--clip-dir`, `--asset-dir`, `--logo`, `--font-dir`); font resolution also falls back to Linux font paths. |
| 2 | Mid-render crash on missing assets | `preflight()` checks the source video, every referenced clip, and the logo file up front, and raises one aggregated `PreflightError` listing everything missing before any frame is written. |
| 3 | 4.4–8.2s static holds | Any `FULL_CHAR`/`FULL_FLOW` shot longer than `--interrupt-interval` (default 3.0s, matching the skill target) gets a deterministic Ken-Burns scale pulse (`interrupt_progress` + `apply_pattern_interrupt`) recurring at that cadence — no new footage required. |
| 4 | Captions could overflow | `wrap_to_safe_width()` measures real glyph widths against a safe pixel budget and rebalances into ≤2 lines; the caption card height is computed from the actual wrapped line count instead of being fixed. |
| 5 | Hard-cut outro | `OUTRO_FLOW` now fades the card, logo, and CTA text in/out over 0.4s based on shot position. |
| 6 | No QC | `run_qc()` writes a JSON report checking output decodability, resolution match, duration within tolerance, and whether the achieved interrupt cadence met the requested interval; the CLI exits non-zero if any gate fails. |
| 7 | Timeline/captions hardcoded in Python | Moved into `server/render_configs/profitbricks_0901.json`, loaded via `RenderConfig.from_json()`, so a new video is a new config file, not a new script. |

**Not changed:** the shot boundaries and caption text from the original
`TIMELINE`/`SUBTITLES` are preserved verbatim in
`render_configs/profitbricks_0901.json` — the narrative and Hinglish
captions were not touched, since they are hand-authored and outside what
can be verified from the repository alone.

## 4. Verification performed

Because the required inputs (`D:\Downloads\0901.mp4`, the six
`flow_clips/*.mp4` files, and `profit_bricks_new_logo.png`) exist only on
the original author's machine and are not in this repository, an actual
render could not be executed here. What *was* verified in this
environment:

- `python3 -m py_compile server/render_master_v4.py` — passes.
- `interrupt_progress()` produces a repeating peak every `interrupt_interval` seconds (tested numerically).
- `wrap_to_safe_width()` correctly splits a long caption into two width-balanced lines using measured glyph widths.
- `preflight()` raises `PreflightError` with a clear message when the source video is missing (confirmed via a missing-path test), and would similarly aggregate missing clips/logo before touching the render loop.
- The CLI parses all documented arguments with the stated defaults (`--interrupt-interval 3.0`, `--true-peak -1.0`).

To fully validate the render output (frame-accurate cadence, actual caption
rendering, final QC gate pass/fail), run the script with the real
`flow_clips/`, source video, and logo once available:

```bash
python server/render_master_v4.py \
  --source /path/to/0901.mp4 \
  --clip-dir /path/to/flow_clips \
  --asset-dir /path/to/assets \
  --logo profit_bricks_new_logo.png \
  --timeline server/render_configs/profitbricks_0901.json \
  --output storage/deliverables/voxpipe_0901_profitbricks/edited_v4.mp4 \
  --qc-report storage/deliverables/voxpipe_0901_profitbricks/qc_report_v4.json
```

## 5. Recommended follow-ups (not implemented here)

1. Route future deliverables through `production_v4`'s typed `plan → generate → assemble → review → approve` pipeline instead of one-off `render_*.py` scripts, so every deliverable gets an `EditPlan.json` + `qc_report.json` automatically.
2. Investigate the ASR failure directly — likely background music/SFX bleeding into the voice track, or a Whisper model/language setting mismatch for code-switched Hindi-English. Until fixed, do not trust `word_timestamps.json` for auto-captioning on this style of audio.
3. Archive or consolidate the ~80 `render_*`, `produce_*`, `finalize_*`, `test_*` one-off scripts in `server/` — most encode a single hardcoded deliverable and are not reusable, which is what led to this gap in the first place.
