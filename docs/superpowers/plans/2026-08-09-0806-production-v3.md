# 0806 Production V3 Implementation Plan

## Objective

Replace the visually rejected V2 with a separately rendered V3 whose editorial
visual language follows the measured training references by story role.

V2 remains untouched. V3 is written to:

`storage/deliverables/0806-production-v3`

## Visual strategy

- Hook/code: reference #10.
- Product actions: references #5 and #12.
- Risk turn: reference #4 only.
- Evidence: references #10, #12 and #13.
- Ending: reference #10.
- Claims use verified source pixels.
- Explanations use bespoke designed visuals.
- Product actions use tight real UI macros.
- Context uses licensed cinematic footage with complete provenance.

## Implementation tasks

1. Add V3 semantic shot metadata and visual-language audit gates.
2. Add a `--visual-revision v3` production option while preserving the V2
   builder for regression coverage.
3. Source licensed 1080p cinematic footage and record provider, creator,
   source URL, license URL, remote ID, query and SHA-256.
4. Build a 24-shot V3 storyboard with:
   - full desktop UI below 20%;
   - designed explanation between 25% and 45%;
   - cinematic/tactile footage between 15% and 30%;
   - edited evidence between 15% and 20%;
   - one named primary subject per shot;
   - no more than one product action per software shot;
   - no source repeated for more than two consecutive shots.
5. Build a dedicated `Reference0806V3VisualLayer` rather than extending the
   rejected V2 component.
6. Reuse the verified evidence, source audio, aligned transcript, captions,
   local MetaTrader captures and dialogue-safe sound system.
7. Render role diagnostics before the full edit and refine hook, code,
   evidence, risk, product-demo and ending frames.
8. Render/master V3, measure every frame, validate ASR/audio/captions/evidence,
   and create role-matched comparison sheets.
9. Keep `human_approved: false` until the user approves the actual rendered
   pixels.
